## 一、对已有接口的唯一变更

### 1.1 DELETE `/api/notes/:id` 语义变更

**v1 行为**：永久删除。

**二期行为**：移入回收站（写 `notes.deleted_at`），不删除数据。

- 路径、方法、鉴权（登录 + write）、成功响应 `204` 均不变；
- 已删除的笔记再次删除返回 `404`；
- 前端删除确认框文案同步改为「可在回收站中还原」。

**这是二期唯一一处改变已有接口语义的地方。** 其余 v1 接口行为不变。

## 二、回收站 `/api/notes/trash`

全部需要 **登录**；写操作为 **登录 + write**。

### 2.1 GET `/api/notes/trash`

**查询参数**：`limit`、`offset`（沿用 v1 1.5）。

**响应** `200`：

```json
{
  "items": [
    {
      "id": "...",
      "title": "...",
      "content_preview": "正文前 200 字…",
      "folder_id": "uuid 或 null",
      "folder_path": "技术 / Go 或空串",
      "deleted_at": "2026-10-31T12:00:00Z"
    }
  ],
  "total": 3
}
```

- 按 `deleted_at DESC` 排序；
- `folder_path` 由后端拼好（用 `/` 连接祖先文件夹名），原文件夹已不存在时为空串；
- **访问本接口时顺带执行惰性清理**（见第四节），因此列表里不会出现超过保留期的记录。

### 2.2 POST `/api/notes/:id/restore`

**响应** `200`：返回还原后的笔记对象（结构同 v1 6.2）。

**规则**：

- 仅对已在回收站中的笔记有效；
- 清空 `deleted_at`；
- 原 `folder_id` 仍存在则回到原文件夹；为 `NULL`（原文件夹已删）时归入收件箱；
- 笔记已经不在回收站 → `404 not_found`。

### 2.3 DELETE `/api/notes/:id/purge`

**响应** `204`

**规则**：

- 仅对已在回收站中的笔记有效，未删除的笔记返回 `404`；
- 物理删除该行，`note_versions` 级联删除；
- 不可撤销。

### 2.4 DELETE `/api/notes/trash`

**响应** `204`

清空当前用户回收站中的全部笔记（物理删除，版本一并级联删除）。

## 三、历史版本 `/api/notes/:id/versions`

全部需要 **登录 + write**（与编辑同一权限档位）。被软删除的笔记一律 `404`。

### 3.1 GET `/api/notes/:id/versions`

**查询参数**：`limit`、`offset`。

**响应** `200`：

```json
{
  "items": [
    {
      "id": "...",
      "title": "...",
      "created_at": "2026-10-31T12:00:00Z",
      "content_size": 1234
    }
  ],
  "total": 8
}
```

- 按 `created_at DESC`；
- 列表**不返回正文**，只返回标题、时间和正文字符数，供时间线展示；
- 笔记不存在或不属于当前用户 → `404`。

### 3.2 GET `/api/notes/:id/versions/:versionId`

**响应** `200`：

```json
{
  "id": "...",
  "note_id": "...",
  "title": "...",
  "content": "完整 Markdown 源文本",
  "folder_id": "uuid 或 null",
  "tag_ids": ["...", "..."],
  "created_at": "..."
}
```

**错误**：`404 not_found`（版本不存在、不属于该笔记，或笔记不属于当前用户）。

### 3.3 POST `/api/notes/:id/versions/:versionId/restore`

**响应** `200`：返回还原后的笔记对象（结构同 v1 6.2）。

**规则**：

- 把快照中的 `title`、`content`、`folder_id`、`tag_ids` 覆盖到当前笔记；
- **还原本身也会产生一条新快照**（还原前的当前内容），以便再次还原回去；
  还原走与编辑相同的写入路径，因此**同样受 5 分钟合并窗口约束**：窗口内还原不新增快照，窗口外会新增一条；
- 快照中的 `folder_id` 已不存在时归入收件箱；
- 快照中的 `tag_ids` 里不存在的 id 直接跳过；
- 还原后 `updated_at` 刷新，`sort_order` 不变。

## 四、惰性清理

不新增接口、不启动后台任务。在以下时机顺带清理超过 **30 天**的回收站记录（物理删除）：

- 调用 `GET /api/notes/trash`；
- 调用 `DELETE /api/notes/:id`（移入回收站）之后。

保留天数 `30` 是**代码常量**，不从环境变量读取。

## 五、不做的事

- 不提供「回收站里查看历史版本」的入口，回收站与历史版本互不引用；
- 不提供跨笔记的版本浏览、不做版本间批量对比；
- 不提供回收站的搜索与按标签筛选。
