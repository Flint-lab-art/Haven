# frontend — 二期页面与交互

> 本文件回答：二期在 Web 前端新增的页面、导航入口与交互（v1 未覆盖的部分）。
> 依赖：`../v1/frontend/frontend.md`、`../v1/frontend/ui-design.md`、`../api.md`

覆盖规则见 `../README.md` 第二节。v1 的路由表、全局状态、API 客户端约定继续有效，本文件只写新增与变更。

## 一、路由新增

在 v1 私有域路由表基础上新增一条：

| 路径 | 页面 | 调用的接口 | `meta.section` |
|---|---|---|---|
| `/trash` | 回收站 | `GET /api/notes/trash`、`POST /api/notes/:id/restore`、`DELETE /api/notes/:id/purge`、`DELETE /api/notes/trash` | `trash` |

- 与 v1 其他私有域页面一样，未登录跳 `/login`，登录后回到原路径；
- `sections` 判定沿用 `route.meta.section`（侧边栏高亮据此判断）。

## 二、侧边栏入口

在左侧导航中新增「回收站」入口，位置固定在：

```
Logo + 折叠按钮
「浏览」
  笔记 / 搜索 / 标签 / 作品集
<div class="sidebar__spacer">      ← 这里之后插入
  回收站
用户区（头像 + 账户菜单）
```

**规则**：

- 即插在 `sidebar__spacer` 与 `sidebar__user` 之间，把回收站与上面四个“浏览”入口在视觉上分开；
- 使用与 `side-link` 相同的样式类与图标尺寸；
- 选中时高亮判断为 `section === 'trash'`；
- Mini（折叠）模式下与其他导航一致：只显示图标，`data-tip` 提供 tooltip；
- 不加入账户下拉菜单，放在导航区。

## 三、回收站页面

### 3.1 布局

沿用私有域三栏结构的右侧主区域，不与笔记工作台的中间列表栏混用：

- **列表**：每行显示标题、原路径（`folder_path`，为空时不显示）、删除时间；
- 按删除时间倒序；
- 分页沿用 `limit` / `offset`。

### 3.2 交互

| 操作 | 行为 |
|---|---|
| 点击一条 | 右侧显示**只读预览**，复用公开笔记的 Markdown 渲染管线（`renderMarkdown`，经 DOMPurify） |
| 「还原」 | 调 `POST /api/notes/:id/restore`，成功后从列表移除并提示 |
| 「永久删除」 | 二次确认后调 `DELETE /api/notes/:id/purge`，确认框文案必须写明不可恢复 |
| 「清空回收站」 | 页面顶部按钮，二次确认后调 `DELETE /api/notes/trash` |
| 空状态 | 列表为空时显示简短的空状态提示，不显示“清空”按钮 |

**详情只展示 `content_preview`，不展示完整正文。** 软删除后笔记在 `GET /api/notes/:id` 上返回 404，回收站列表按 `api.md` 2.1 只给出 200 字预览。理由：回收站只回答「这篇笔记还在不在」，不承担阅读职责；要看全文请先还原。

### 3.3 明确不做

- 回收站内**不提供历史版本入口**；
- 不提供回收站内编辑、发布、改标签；
- 不提供回收站的搜索与筛选。

## 四、删除入口文案变更

删除笔记的入口仍在中间栏笔记树的行内按钮（`tree-action--danger`），位置与行为不变，只是确认文案改变：

| 场景 | v1 文案 | 二期文案 |
|---|---|---|
| 删除笔记 | 删除后无法恢复 | 可在回收站中还原 |
| 删除文件夹 | （不变） | （不变，仍是先迁移笔记再删文件夹） |

删除成功后当前打开的是该笔记时，仍跳回工作台（与 v1 一致）。

## 五、历史版本浮层

### 5.1 入口

在编辑页 `/notes/:id` 的顶部工具栏 `editor-actions` 内新增图标按钮，位置在**字数统计之后、文件夹下拉之前**：

```
[保存状态]  [字数]  [历史版本]  [文件夹下拉]  [标签]
```

- 随笔输入过程中的状态变化不影响该按钮；
- 新建笔记（`/notes/new`）尚未创建时**不显示**该按钮（没有笔记 id，也就没有版本）。

### 5.2 浮层形态

点击后在同一页面内展开浮层，**不跳转路由**（避免跳走丢上下文，编辑页有 1 秒自动保存）。

```
┌─────────────────────────────────────────────┐
│  历史版本                           [关闭]  │
├──────────┬──────────────────────────────────┤
│ 20:15    │  对比：该版本 ↔ 当前内容          │
│ 19:40    │   未变的行                        │
│ 18:02    │  + 新增的行                       │
│          │  - 删除的行                       │
│          │                                  │
│          │        [还原到此版本]             │
└─────────────────────────────────────────────┘
```

- **左栏**：版本时间线，按时间倒序，显示时间与标题；点击切换选中版本；
- **右栏**：选中版本与**当前编辑器内容**做 DIFF；
- **DIFF 基准固定为「该版本 ↔ 当前内容」**，不做相邻两版对比；
- 只对正文做 DIFF，标题如有变化在顶部单独提示一句，不参与行级对比；
- 点击外部或 `Esc` 关闭浮层；收起判断使用 `pointerdown`（不用 `focusout`）。

### 5.3 还原

- 「还原到此版本」调用 `POST /api/notes/:id/versions/:versionId/restore`；
- 还原前需二次确认，文案说明「当前内容会被覆盖，且仍可在历史版本中找回」；
- 还原成功后刷新编辑器内容（先 `sync()` 再覆盖，避免与自动保存竞争），关闭浮层，保存状态回到已保存。

### 5.4 明确不做

- 不做左右分栏的完整双文档对比，只用单栏 DIFF；
- 不做版本的手动命名、打标签、手动创建快照；
- 不做版本删除；
- 不做跨笔记的版本查看。

## 六、样式

- 全部样式写在 `src/style.css`，沿用 HIG 语义色与现有字号阶梯；
- DIFF 的新增/删除用语义色（成功/危险）的低透明度背景，不引入新配色体系；
- 不引入组件库、不引入 DIFF 第三方库——正文是纯文本，按行比较即可。
