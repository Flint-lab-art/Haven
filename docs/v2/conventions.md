# conventions — 二期约定与禁令变更

> 本文件回答：二期相对 v1 约定做了哪些补充，以及哪些禁令被解除、哪些是二期新增的禁令。
> 依赖：`../v1/conventions.md`

覆盖规则见 `../README.md` 第二节。v1 `conventions.md` 第一、二、三、五节**继续有效**，本文件不重复；第四节（硬性禁令）按本文件第二节增补。

## 一、二期约定补充

1. **二期代码仍在同一个 `backend/`、`frontend/` 仓库内增量演进**，不新建并列目录。
2. **现有 API 的行为语义原则上不变**。二期唯一的例外是 `DELETE /api/notes/:id` 从“永久删除”改为“移入回收站”，见 `api.md` 1.1。
3. **给已有表加列可以，但不得修改已有列的类型与约束**。二期对 `notes` 只新增 `deleted_at` 一列。
4. **可见性条件仍是全库唯一一份**，写在 `auth.VisibilityPublic` / `auth.VisibilityOwnedOrPublic` 常量里。二期把 `deleted_at IS NULL` 并入这两个常量，**禁止**在任何 handler 或 service 里另写一份删除状态判断。
5. **迁移必须成对提供 `up` 与 `down`**，`down` 只回滚自身新增对象。
6. **新增的代码常量**（不读环境变量）：回收站保留 30 天、版本合并窗口 5 分钟。

## 二、禁令变更

### 2.1 解除的禁令

v1 `conventions.md` 第四节的以下条目在本期**不再生效**：

| v1 条目 | 二期处理 |
|---|---|
| 「`conventions.md` 第四节只增不删；确需解除禁令时，写明原因和日期」 | 本条**仍然生效**。解除任何禁令必须在本表登记，不得只在代码里做。 |

**本期未解除任何 v1 禁令。** 回收站与历史版本都在 v1 允许的范围内（PostgreSQL 唯一真值源、手写 SQL、Gin、纯 SPA）。

### 2.2 新增的禁令

以下事项二期明确不做，生成代码时不得自行添加：

- **不做回收站里查看历史版本**，两个功能互不引用；
- **不做后台定时清理任务**，清理一律惰性触发；
- **不做版本的手动快照、命名、删除**；
- **不引入 DIFF 第三方库**，正文按行比较即可；
- **不引入新的测试框架或 mock 库**；
- **不做 LLM 相关功能**（翻译、润色、对话），留待三期。
