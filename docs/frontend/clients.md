- TUI 与 Neovim 插件作为次级客户端，只覆盖**读写笔记 + 检索**主路径；
- 不做功能对等，其余功能交给 Web；
- 通过 API Token 鉴权，不引入新的鉴权方式；
- 以服务端为准，不做离线编辑与冲突合并。

## 三、本期不做的事

- 不在 `backend/` 或 `frontend/` 下创建任何 TUI / Neovim 相关代码；
- 不在 `api.md` 中为次级客户端新增接口（现有接口已足够覆盖读写 + 检索）；
- 不在 `architecture.md` 的目录结构中预留 TUI / Neovim 目录。

具体设计（Token 配置方式、覆盖哪些接口、错误处理）等第二版动工时另写，不在本文件预先展开。
