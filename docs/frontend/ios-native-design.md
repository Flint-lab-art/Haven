# Haven iOS 原生设计方案

> 状态：草案 v0.1（2026-11）
> 依据：`frontend/src/router/mobile.ts`、`frontend/src/views/mobile/*`、`frontend/src/components/mobile/*`、`frontend/src/style.css` 的移动端段（`.m-*`）
> 目标平台：iPhone，竖屏，iOS 18+；使用 Xcode 26 SDK 构建，在 iOS 26 上自动获得 Liquid Glass。
> 本文只讲「长什么样、怎么交互、为什么」；后端接口与数据模型以 `docs/api-conventions.md`、`docs/data-model.md` 为准。

---

## 0. 一句话

把 `/m/` 已经验证过的三件事——**看统计、记一笔、管账户/Issue**——做成一个原生 iOS App：
**记账是主角，统计是默认落点，其余收进「我的」**。不把 PC 全功能搬进手机，也不为了「原生」重造一套信息架构。

设计上的三条硬约束：

1. **单手完成记账**：从打开到保存，拇指不离开屏幕下半区。
2. **金额是视觉主角**：一屏只有一个 40pt 的数字，其余信息退到脚注。
3. **系统优先**：能用系统控件（TabView、sheet、swipeActions、DatePicker、Swift Charts）就不自绘；只保留 Web 端已经证明必要的三个自定义件：数字键盘、分类下钻网格、统计区间胶囊。

## 1. 设计输入：Web 移动端现状

### 1.1 路由与页面

`router/mobile.ts` 是一套与 PC 完全独立的移动端路由树，入口由路径 `/m/` 决定，不做 UA 嗅探。

| Web 路径 | 页面 | 原生对应 |
| --- | --- | --- |
| `/m/` | 统计（默认） | Tab「统计」 |
| `/m/ledger` | 记账 | Tab「记账」 |
| `/m/me` | 我的 | Tab「我的」 |
| `/m/me/accounts` | 账户 | 我的 → 账户（push） |
| `/m/me/settings` | 设置 | 我的 → 设置（push） |
| `/m/me/appearance` | 外观 | 设置 → 外观（push） |
| `/m/me/login-logs` | 登录日志 | 设置 → 登录日志（push） |
| `/m/me/issues` | Issue 列表 | 我的 → Issue（push） |
| `/m/me/issues/new` | 新建 Issue | Issue → 新建（sheet） |
| `/m/me/issues/:id` | Issue 详情 | Issue → 详情（push） |

### 1.2 已经成立的设计决策（原样继承）

| 决策 | 出处 | 原生是否保留 |
| --- | --- | --- |
| 底部只有 3 个 tab，记账在中间 | `MobileLayout.vue` | 保留。中间是拇指最容易够到的位置 |
| 统计四粒度看不同的图：周/月折线，季/年柱状 | `MobileStats.vue` | 保留，改用 Swift Charts |
| 区间不越过今天；到当前段隐藏「下一段」 | `MobileStats.vue`、`MobileTimePicker.vue` | 保留，并补上左右滑动切段 |
| 记账用底部抽屉 + 自绘数字键盘 | `MobileLedger.vue`、`MobileKeypad.vue` | 保留，键盘是记账的签名交互 |
| 分类下钻：先一级，再二级 | `MobileCategoryPicker.vue` | 保留，4 列 LazyVGrid |
| 只有收入一个一级分类时直接展开 | `MobileCategoryPicker.vue` | 保留 |
| 左滑露出删除，不「滑到底直接删」 | `SwipeRow.vue` | 保留语义，改用系统 `.swipeActions` |
| 金额一律整数分，前端只负责格式化 | `api/ledger.ts`、`utils/ledger.ts` | 保留；Swift 用 `Int` 分 + `Decimal` 格式化 |
| 加载用骨架，不用转圈 | `.m-skeleton` | 保留 |
| 空态给下一步动作 | `.m-empty` | 保留并强化 |

### 1.3 需要在原生端重新决定的事

| 议题 | Web 做法 | 原生方案 | 理由 |
| --- | --- | --- | --- |
| 底部栏 | 自绘悬浮胶囊 + `backdrop-filter` | 系统 `TabView` | 系统自带安全区、无障碍、状态恢复；iOS 26 自动是液态玻璃 |
| 时间选择 | 自绘三列滚轮 | 系统 `DatePicker`（`.wheel`） | 系统滚轮有触感、VoiceOver、Dynamic Type |
| 左滑删除 | 自绘 `SwipeRow` + 手势 | `.swipeActions` | 系统手势与「操作」无障碍菜单免费获得 |
| 图表 | 手写 SVG | Swift Charts | 动画、深浅色、图表无障碍描述 |
| 主题 | 5 套完整配色（含深色底） | 系统浅/深 + 可选强调色 | 自定义大底色会与系统材质、对比度打架 |
| 弹层 | `Teleport to body` 修层叠 | `.sheet` / `.confirmationDialog` | 原生层级由系统管理 |
| 登录 | Cookie 会话 | 会话 token 存 Keychain，请求带 `havenToken` 头 | API Token 是只读的，不能承担原生 App 的写操作 |
| 部署 | 同源 | 首次启动配置服务器地址 | 自托管产品没有固定域名 |

## 2. 产品目标与非目标

### 2.1 目标

1. **3 秒记一笔**：从点开「记一笔」到保存成功 ≤ 3 次点击（金额 → 保存，分类与账户有默认值）。
2. **打开就知道钱花到哪**：启动落在统计，首屏 1 秒内出现结余与本月走势。
3. **比 PWA 更可靠**：锁屏、后台、网络抖动时不丢草稿；保存失败可重试。
4. **真正属于这台手机**：Face ID 解锁、主屏/锁屏小组件、Siri/快捷指令、控制中心一键记账。

### 2.2 非目标（v1 明确不做）

- 不移植笔记模块（`/m/` 本来就没有）。
- 不做多用户、多币种、多租户。
- 不做横屏专属布局与 iPad 分栏；iPad 先按「可读宽度 600pt 的居中列」自适应。
- 不做自定义全屏主题背景；主题收敛为「系统外观 + 强调色」。
- 不做离线写入队列（除非后端先提供幂等键，见 §11.3）。
- 不做推送通知营销；最多做本地预算提醒。

## 3. 信息架构与导航

### 3.1 结构

```
App
├── 统计（Tab，默认）
│   └── 粒度选择（sheet）
├── 记账（Tab）
│   ├── 记一笔（sheet，新建/编辑共用）
│   │   └── 选择时间（sheet）
│   └── 删除确认（confirmationDialog）
└── 我的（Tab）
    ├── 账户（push）
    │   └── 新建账户（sheet）
    ├── Issue（push）
    │   ├── 新建 Issue（sheet）
    │   └── 详情（push）→ 编辑（sheet）
    └── 设置（push）
        ├── 外观（push）
        ├── 登录日志（push）
        ├── 账号安全（push，v1.1）
        ├── 会话（push，v1.1）
        └── API Token（push，v1.1）
```

### 3.2 导航规则

- **Tab 内一律 `NavigationStack`**，push 保留返回手势；Tab 切换保留各自栈（系统行为）。
- **录入、时间、粒度、新建 Issue、新建账户用 sheet**，不用 push：这些是「完成一件事就关掉」的模态任务。
- **详情用 push**：用户会从详情返回列表继续看。
- **删除用 `confirmationDialog`**，不用 `alert` 堆两个按钮；文案带对象名，例如「删除「午饭」？」。
- **深链**：`haven://ledger`、`haven://entry`、`haven://stats`、`haven://issue/<id>`。Universal Link 映射到同一路由；Web 端 `/m/` 继续可用。
- **状态恢复**：记住上次 Tab 与统计粒度，但不恢复 sheet。

### 3.3 启动落点

默认进「统计」，与 Web 一致：打开先看账，而不是先面对一个表单。

「记一笔」的快捷入口放在系统层：

- 主屏小组件按钮 → `haven://entry`（App 启动后自动弹出录入 sheet）。
- 长按 App 图标的 Quick Action「记一笔」。
- 控制中心控件（iOS 18+）。
- Siri / 快捷指令「用 Haven 记一笔 35 元午饭」。

## 4. 设计系统

### 4.1 色彩

原生不再复制 `style.css` 的五套底色，而是用系统语义色。这样深色模式、增强对比度、降低透明度都由系统接管。

| 语义 | Web token | iOS |
| --- | --- | --- |
| 页面底色 | `--bg-grouped` | `.systemGroupedBackground` |
| 卡片 | `--bg` / `--bg-elevated` | `.secondarySystemGroupedBackground` |
| 主文字 | `--label` | `.label` |
| 次文字 | `--label-2` | `.secondaryLabel` |
| 弱文字 | `--label-3` | `.tertiaryLabel` |
| 占位/禁用 | `--label-4` | `.quaternaryLabel` |
| 分割线 | `--sep` | `.separator` |
| 浅填充 | `--fill` | `.tertiarySystemFill` |
| 强调 | `--accent` `#007AFF` | `Color.accentColor`（可换） |
| 收入/成功 | `--success` `#34C759` | `Color(hex: 0x34C759)` |
| 危险/超支 | `--danger` `#FF3B30` | `.red` / `Color(hex: 0xFF3B30)` |
| 警告 | `--warning` `#FF9500` | `.orange` |

**强调色预设**（外观页，替代 Web 的 5 套主题）：

| 名称 | 色值 | 来源 |
| --- | --- | --- |
| 系统蓝（默认） | `#007AFF` | 浅色主题 |
| 夜蓝 | `#7AA2F7` | Tokyo Night |
| 琥珀 | `#FABD2F` | Gruvbox |
| 薰衣草 | `#CBA6F7` | Catppuccin |
| 极地青 | `#88C0D0` | Nord |

原则：**底色永远跟系统走，只有强调色、选中态、图表支出线跟着变**。收入绿、危险红不随强调色改变，避免语义漂移。

**分类色板**：沿用 Web 的「按分类名取色相」思路，固定 6 个色相族（红/橙/绿/青/蓝/紫），每族提供浅色/深色两个变体，饱和度与亮度按 WCAG AA 校正。不要在原生端用 `hsl()` 动态算色。

### 4.2 字体

用 SF Pro（系统字体），不引入第三方字体。数字一律 `.monospacedDigit()`。

| 用途 | Web | iOS |
| --- | --- | --- |
| 一级页大标题 | 28/1.2 700 | `.largeTitle`（34/41，粗体），滚动后收为 inline |
| 二级页标题 | 28/1.2 700 | `.title2`（22/28）或 inline `.headline` |
| 结余/金额 | 40/1.1 700，字距 -1.2 | 40pt `.system(size: 40, weight: .bold)`，`.monospacedDigit()` |
| 行主标题 | 14/1.5 | `.body`（17/22） |
| 行副标题 | 12/1.4 | `.footnote`（13/18） |
| 分组标题 | 12/1.4 | `.footnote`，`.secondaryLabel`，可用大写 |
| 按钮 | 16/1.2 600 | `.headline`（17/22 半粗） |
| 标签/脚注 | 12/1.4 | `.caption`（12/16） |

规则：

- 只用系统文字样式，支持 Dynamic Type；金额与键盘数字允许放大到 AX2，再大改为两行。
- 中文不设负字距；只有 40pt 金额用 `-1.0` 收紧。
- 不用 15pt、18pt 这类「中间字号」；需要层级就用字重和颜色。

### 4.3 间距与圆角

- 8pt 节奏：4 / 8 / 12 / 16 / 24 / 32。
- 页面左右边距 **16pt**；卡片内边距 **16pt**；分组之间 **24pt**。
- 卡片圆角 **16pt**，连续圆角（`.continuous`）；按钮 **12pt**；胶囊用 `Capsule()`。
- 触控目标 ≥ 44×44pt；键盘键高 52pt；列表行最小 44pt，双行行高约 60pt。
- 分割线只在同一组内出现，且从文字起始位置缩进（系统 `List` 默认行为）。

### 4.4 材质与层次

- 底部 tab 用系统 `TabView`，iOS 26 自动液态玻璃；**不要自绘毛玻璃**。
- Sheet 用系统材质与圆角（`.presentationCornerRadius(24)`），拖拽指示条可见。
- 卡片不用阴影，用底色和间距分组；只有悬浮「记一笔」按钮有轻投影。
- 深色模式下不额外加高光；系统材质已经处理。

### 4.5 图标

- Tab 与导航用 SF Symbols：`chart.bar.xaxis`（统计）、`wallet.pass`（记账）、`person.crop.circle`（我的）。
- 分类继续用 emoji（与 Web 数据一致），不要为分类另建一套 SF Symbols 映射，否则两端图标会漂移。
- 状态/优先级用「文字 + 形状 + 颜色」三重编码，不只靠颜色。

## 5. 页面设计

### 5.1 统计（Tab 1）

**这一屏只回答一件事：这段时间钱花得怎么样。**

```
┌─────────────────────────────┐
│ 统计                    ⚙︎  │  ← 大标题（滚动后收起）
│                             │
│  ‹   周 · 11/17–11/23   ›   │  ← 区间胶囊，点中间换粒度
│                             │
│ ┌─────────────────────────┐ │
│ │ 结余                     │ │
│ │ ¥ 1,284.50              │ │  ← 40pt，负数红色
│ │ 支出 ¥862.00 · 收入 ... │ │
│ └─────────────────────────┘ │
│                             │
│ ⚠ 餐饮、交通 超出预算        │  ← 仅超支时出现
│                             │
│ ┌─────────────────────────┐ │
│ │ 每天收支                 │ │
│ │   ╱╲    ╱╲              │ │  ← 折线（周/月）
│ │  ╱  ╲__╱  ╲___          │ │
│ │  17 18 19 20 21 22 23   │ │
│ └─────────────────────────┘ │
│                             │
│ ┌─────────────────────────┐ │
│ │ 钱花在哪                 │ │
│ │    ◕  ¥862              │ │  ← 圆环 + 图例
│ │  餐饮 42%      ¥362      │ │
│ │  交通 21%      ¥181      │ │
│ └─────────────────────────┘ │
│                             │
│ ┌─────────────────────────┐ │
│ │ 预算明细       按月折算   │ │
│ │ 餐饮   ¥362  120%  ████ │ │
│ │ 预算 ¥300 · 超出 ¥62     │ │
│ └─────────────────────────┘ │
└─────────────────────────────┘
```

**区间胶囊**（`RangePill`）

- 结构：左箭头 / 中间「粒度徽章 + 区间文字」/ 右箭头。
- 中间可点，弹「统计粒度」sheet：四行，每行「名称 + 一句人话 + 勾选」。
  - 周「哪天花得最多」/ 月「钱花在哪」/ 季「三个月对比」/ 年「全年走势」。
- 右箭头在当前段隐藏但保留占位，避免标题左右跳。
- 原生增强：内容区左右滑切换上一段/下一段；到头时回弹并给 `.warning` 触感。
- 粒度切换后回到当前段（与 Web 一致）。

**结余卡**

- 极淡的强调色渐变（16pt 圆角），不是纯白卡；深色模式降低混色比例。
- 结余 = 收入 − 支出；负数红色并带 `−`。
- 脚注：支出、收入、笔数，用 `·` 分隔。

**图表**（Swift Charts）

| 粒度 | 形态 | 横轴 |
| --- | --- | --- |
| 周 | 折线 + 面积 | 每天，7 点 |
| 月 | 折线 + 面积 | 按自然周分桶，4–5 点 |
| 季 | 柱状 | 每月，3 根 |
| 年 | 柱状 | 每月，12 根 |

- 支出用强调色，收入用绿色；两条共用纵轴。
- 隐藏 Y 轴网格与图例，保留一条基线；图例用自定义小圆点。
- 横轴最多 6 个标签，按点数抽样，最后一项必须有标签。
- 空数据：「这一周还没有记录。」不画空图。
- 切换粒度用 `.smooth(duration: 0.35)` 做形变；Reduce Motion 时只淡入。

**圆环**

- 优先支出分类；没有支出时退回收入分类，中心标签随之变「收入」。
- 中心显示总额；图例四列：色点、名称、百分比、金额。
- 相邻扇区留 2pt 间隙；只有一个分类时不留。
- 点击图例某行可高亮对应扇区（原生增强，Web 没有）。

**预算明细**

- 只对「周 / 月」显示；周按天折算并在标题右侧标注「按月折算」。
- 每行：名称、已花、百分比、进度条；超支时进度条、百分比、脚注一起变红。
- 排序按使用比例从高到低，最危险的先出现。

**状态**

| 状态 | 表现 |
| --- | --- |
| 加载 | 骨架：标题 46%、结余块、图表块，不用转圈 |
| 空 | 结余 0 + 「这一周还没有记录」+「记一笔」按钮 |
| 错误 | 内联提示条 + 「重试」；保留上一次成功数据并标「上次更新 10:32」 |
| 超支 | 顶部警告条，列出超支分类，点进预算明细 |

### 5.2 记账（Tab 2）

**这一屏只回答一件事：这个月花了多少，最近几笔是什么。**

```
┌─────────────────────────────┐
│ 记账              ‹ 11月 ›  │
│                             │
│  支出        收入       笔数 │
│  ¥862.00    ¥2,146.50    18 │
│                             │
│  本月预算   ¥862 / ¥3,000   │
│  ████████░░░░░░░░░░  29%    │
│                             │
│  今天 · 周三        -¥42.00 │
│  ┌─────────────────────────┐│
│  │ 🍜 午饭                 ││
│  │ 餐饮 · 微信 · 公司楼下  ││
│  │                  -¥32.00││
│  └─────────────────────────┘│
│  昨天 · 周二        -¥118.00│
│  …                          │
│                             │
│                         (+) │  ← 悬浮按钮
└─────────────────────────────┘
```

**头部**

- 大标题「记账」+ 月份步进器（‹ 11月 ›）。
- 到当前月隐藏「下个月」，不能翻到未来。
- 月份切换用 `.snappy` 动画 + `.selection` 触感；切换时列表淡出再淡入，不整页闪白。

**月度汇总**

- 三格：支出、收入、笔数；收入绿色。
- 数字 `.monospacedDigit()`，等宽避免切换月份时跳动。

**预算条**

- 只有设置过预算才显示；`已花 / 预算` + 百分比进度条。
- 超支：进度条与文字变红，并在统计页顶部同步警告。

**流水列表**

- 按天分组；组头「今天/昨天/具体日期 + 星期 + 当日合计」。
- 行：emoji 分类图标、主标题（分类名或「转账」）、副标题（一级分类 · 账户 · 备注）、右侧金额。
- 支出默认色、收入绿色、转账次级灰。
- 点行 → 编辑 sheet；左滑 → 编辑 / 删除（系统 `.swipeActions`，删除 `role: .destructive`）。
- 空态：「这个月还没有记录」+「点右下角记一笔」；没有账户时顶部给「还没有账户，先去建一个 →」。

**悬浮按钮**

- 52pt 圆形，强调色，右下角，位于 tab bar 上方 16pt；轻投影。

- 关闭保护：表单有改动时 `interactiveDismissDisabled`，下滑先确认「放弃这笔记录？」。

**选择时间 sheet**

- 用系统 `DatePicker`，`.datePickerStyle(.wheel)`，日期与时间两个滚轮。
- 范围：本月 1 号 → 今天 23:59；编辑上月流水时允许保留原日期。
- 顶部「取消 / 选择时间 / 确定」；确定后写回草稿。
- 不用自绘滚轮：系统滚轮在 VoiceOver、动态字体、触感上都更好。

### 6.1 数字键盘

| 项目 | 规范 |

### 6.2 分类下钻

- 一级 4 列网格，单元格 62pt 高；emoji 20pt + 名称 12pt。
- 点一级：立即记为选中（「综合」语义），并整块换成它的二级。

### 6.3 左滑

- 用系统 `.swipeActions(edge: .trailing)`：编辑（灰）、删除（红）。
- 不做「滑到底直接删」；删除必须二次确认。
- VoiceOver 通过「操作」转子提供同样两项，不依赖手势。

### 6.4 Sheet

- 录入 sheet：`.presentationDetents([.large])`，拖拽指示条可见，圆角 24。
- 时间/粒度：`.presentationDetents([.medium])` 或 `.height(360)`。
- 键盘弹出时内容上移，键盘区固定底部；分类网格可滚动，金额与键盘不被顶出屏幕。

### 6.5 图表手势

- 点按/长按图表显示该点数值（`chartOverlay` + `RuleMark`），松手消失。
- 周/月折线支持横向拖动查看数值；不与页面的区间滑动冲突（图表内优先）。
- 圆环点按扇区高亮，再点取消。

## 9. 无障碍与本地化

- **Dynamic Type**：所有文字用系统样式；金额上限 AX2，再大改为两行；键盘与列表在 AX3 下仍可操作。
- **VoiceOver**：
  - 金额读作「支出 32 元」而不是「负三二点零零」。
  - 图表提供 `AXChartDescriptor`（Swift Charts 自带），圆环每个扇区有独立标签。
  - 左滑操作通过 accessibility actions 暴露。
  - 状态/优先级不只靠颜色，读「待办，高优先级」。
- **对比度**：正文 ≥ 4.5:1，大字与图标 ≥ 3:1；深色模式下分类色板单独校正。
- **触控目标**：≥ 44×44pt；键盘 52pt；tab 用系统。
- **降低透明度 / 增强对比度**：系统 tab 与 sheet 自动响应；不要用固定半透明色覆盖。
- **语言**：v1 简体中文；金额 `¥`、千分位、两位小数；时间用「今天/昨天/11 月 3 日」，相对时间「3 分钟前」。
- **时区**：业务时区固定 `Asia/Shanghai`（与后端 `haven.time-zone` 一致）；不要用设备时区算「今天」。

## 11. 技术架构（设计约束）

### 11.1 分层

```
HavenApp
├── HavenUI          设计 tokens、通用组件、图表封装
├── HavenCore        领域模型、金额/时间工具、格式化
├── HavenAPI         APIClient、DTO、错误映射、鉴权
├── HavenStore       Observation 状态、缓存、快照
└── HavenFeatures    Stats / Ledger / Me / Issues / Settings
```

- SwiftUI + Observation（`@Observable`），Swift 6 严格并发。
- 网络：`URLSession` + `async/await`；DTO 用 `Codable`，统一 `.convertFromSnakeCase`（后端 JSON 全 `snake_case`）。
- 金额：`Int` 分，禁止 `Double` 参与计算；格式化用 `NumberFormatter`（`zh_CN`，`¥`，两位小数）。
- 时间：`ISO8601DateFormatter` 解析，展示时转 `Asia/Shanghai`。
- 缓存：SwiftData（只读快照 + 最近流水）；写入以服务端为准。
- 依赖注入：`Environment` + 协议，便于预览与测试。

### 11.2 鉴权与会话

后端是双通道：Sa-Token Cookie 会话（读写）与 `Authorization: Bearer haven_ro_…` API Token（只读，且 `SESSION` 级端点 403）。
**原生 App 必须使用会话通道**，不能只靠 API Token。

推荐流程：

1. `POST /api/auth/login`（`username`、`password`、`trust_device`）。
2. 若 `totp_required`，用 `temp_token` 调 `POST /api/auth/login/totp`。
3. 从响应 `Set-Cookie` 取 `havenToken`，存 Keychain（`kSecAttrAccessibleAfterFirstUnlockThisDeviceOnly`）。
4. 后续请求带 `havenToken: <token>` 头；不依赖 `HTTPCookieStorage` 的持久化。
5. 401 → 清 token → 重新登录 sheet；403 → 展示权限说明。
6. 登出：`POST /api/auth/logout` → 清 Keychain、SwiftData、App Group 快照。

**需要后端配合的点**：登录响应目前只回 `user / totp_required / temp_token`，会话 token 只在 `Set-Cookie` 里。解析 Cookie 可行但脆弱。建议二选一：

- 方案 A（推荐）：登录成功响应体增加 `session_token` 字段（仅 HTTPS、仅原生客户端），或新增 `/api/auth/native/login`。
- 方案 B：原生端解析 `Set-Cookie`，把 `havenToken` 取出存 Keychain。

另外，账号安全/会话/API Token 这些 `SESSION` 端点，v1 若用 `SFSafariViewController` 打开，需要与 Web 共享 Cookie，体验会割裂；建议 v1.1 原生实现。

### 11.3 离线与写入

- **v1 只读缓存，不做离线写入**：记账失败就提示重试，草稿留在 sheet 里。
- 原因：当前后端没有客户端幂等键，离线重试可能重复记账。
- v2 若要做离线队列，后端需支持 `client_request_id`（按用户唯一）或 `Idempotency-Key`；客户端在重试时复用同一个键。
- 只读缓存策略：打开页面先显示上次快照并标时间，再后台刷新；下拉刷新强制请求。

### 11.4 接口映射

| 页面 | 接口 |
| --- | --- |
| 统计 | `GET /api/ledger/stats?from&to`、`GET /api/ledger/budgets?month` |

### 11.5 首次启动：服务器配置

自托管产品没有固定域名，原生 App 必须有一步「连接服务器」：

```
┌─────────────────────────────┐
│ 连接你的 Haven               │
│                             │
│ 服务器地址                   │
│ ┌─────────────────────────┐ │
│ │ https://haven.example   │ │
│ └─────────────────────────┘ │
│                             │
│ [ 测试连接 ]                 │
│ ✓ 已连接 · Haven 3.2.0      │
│                             │
│ [ 继续 ]                     │
└─────────────────────────────┘
```

- 只接受 `https://`；调试构建允许局域网 `http://` 与自签名证书。
- 测试连接：`GET /api/health` + `GET /api/app-config`。
- 地址存 Keychain/`@AppStorage`；换服务器等于换账号，需要重新登录并清缓存。
- 错误文案：地址格式、无法连接、证书不受信任、服务端版本过低。

## 14. 验收清单

**视觉**

- [ ] 每个 Tab 只有一个大标题；滚动后收起为 inline。
- [ ] 金额是屏幕最大字号；同一屏没有第二个 40pt 数字。
- [ ] 卡片圆角 16pt 连续圆角；按钮 12pt；胶囊用于分段与标签。
- [ ] 没有自绘毛玻璃；tab 与 sheet 用系统材质。
- [ ] 浅色/深色/增强对比度下都检查过；分类色在深色下可区分。

**交互**

- [ ] 记账全程拇指可达：分类、金额、账户、保存都在下半屏。
- [ ] 数字键盘支持双击退格清空、硬件键盘、VoiceOver。
- [ ] 分类下钻只有两步；收入只有一个一级时直接展开。
- [ ] 左滑只露出操作，不直接删除；删除有确认。
- [ ] 区间到当前段时右箭头隐藏但占位，标题不跳。
- [ ] 所有 sheet 有拖拽指示条；有未保存内容时关闭要确认。

**状态**

- [ ] 每个列表都有加载骨架、空态、错误重试、离线提示。
- [ ] 401 重新登录后回到原页面，草稿不丢。
- [ ] 403 有解释，不显示「重试」。
- [ ] 保存成功只用触感 + 短暂反馈，不弹 alert。

**无障碍**

- [ ] VoiceOver 能读完一笔流水并操作编辑/删除。
- [ ] 图表有可朗读的摘要与数据点。
- [ ] Dynamic Type AX3 下不截断关键金额与按钮。
- [ ] 所有触控目标 ≥ 44pt；颜色不是唯一信息载体。
- [ ] Reduce Motion 下没有位移与弹跳。

**工程**

- [ ] 金额只用 `Int` 分；没有 `Double` 参与计算。
- [ ] 时间按 `Asia/Shanghai` 解释「今天」。
- [ ] token 只在 Keychain，不写日志、不进 UserDefaults。
- [ ] 换服务器会清空旧账号缓存。
- [ ] 小组件只读 App Group 快照，不直接请求 API。

## 15. 需要拍板的问题

1. **原生与 Web 的关系**：原生是否长期双轨维护？还是原生只做记账高频场景，其余仍回 Web？
2. **会话 token 下发**：后端是否愿意在登录响应里返回 `session_token`，还是原生解析 `Set-Cookie`？（影响 §11.2）
3. **主题策略**：接受「系统外观 + 强调色」，还是必须保留 Web 的 5 套完整底色？后者会显著增加深色模式与对比度成本。
4. **离线写入**：v1 是否接受「只能在线记账」？若不能，需要先加幂等键。
5. **最低系统版本**：iOS 18 还是 iOS 26？iOS 26 可以用新版 Liquid Glass 与控制中心控件，但放弃一部分老设备。
6. **服务器发现**：手动输入地址是否足够？要不要做二维码/局域网发现？
7. **API Token 的定位**：继续只读、只服务快捷指令，还是未来支持写入？这会改变原生 App 的鉴权设计。
8. **iPad**：v1 是否只保证 iPhone？iPad 分栏（列表 + 详情）可以放到 v2。
