# frontend — 四期图片上传

> 本文件回答：编辑器插图、文件夹图标上传的前端交互与展示规则。
> 依赖：`../v1/frontend/frontend.md`、`../v1/frontend/ui-design.md`、`../api.md`

覆盖规则见 `../../README.md` 第二节。v1 的路由、全局状态、API 客户端约定继续有效。

## 一、上传客户端

新增 `frontend/src/api/uploads.ts`：

```ts
export interface UploadResult {
  url: string
  name: string
  size: number
  mime: string
}

export function uploadImage(file: File): Promise<UploadResult>
```

- 用 `FormData` 提交，字段名 `file`；
- **不要**给请求设置 `Content-Type`，让浏览器自动带上 boundary；
- 现有 `request()` 封装默认按 JSON 处理，上传需要单独走 `fetch` 或给封装加分支。

## 二、编辑器插图（替换 v1 粘贴行为）

### 2.1 粘贴图片

现在粘贴图片会被 Milkdown 以 base64 内嵌进正文。本期改为：

```
用户粘贴图片
  → 拦截 paste 事件里的 image/* 项
  → POST /api/uploads
  → 成功后把 ![文件名](url) 插入光标处
  → 失败：提示「图片上传失败」，不插入任何内容
```

**规则**：

- 上传中在光标处显示占位（可选，不做也不影响）；
- **一次粘贴多张图**：逐个上传，全部成功后按顺序插入；
- **不拦截文本**：只有剪贴板里有 `image/*` 时才走上传，其他情况交给 Milkdown 默认处理。

### 2.2 拖拽图片

同粘贴：拖入 `image/*` 文件时上传并插入，不插入 base64。

### 2.3 阅读态

`renderMarkdown` 渲染 `![](/uploads/...)` 时：

- 相对路径直接作为 `src`，与站点同域；
- 图片最大宽度 100%，高度自适应，圆角 8px；
- 加载失败时显示 alt 文本，不显示破图图标。

## 三、文件夹图标（扩展 v1 图标面板）

### 3.1 面板结构

v1 的面板是「内置 emoji + 手动输入 + 恢复默认」。本期在顶部增加一行：

```
┌─────────────────────────────────┐
│  [ 上传图片 ]                    │  ← 新增
├─────────────────────────────────┤
│  📚 📁 💡 🎯 🌱 …               │  ← 内置 emoji（不变）
│  手动输入：[________]            │
│  恢复默认                        │
└─────────────────────────────────┘
```

### 3.2 上传流程

1. 点「上传图片」选文件，或**直接粘贴图片**（面板聚焦时）；
2. 上传成功后调 `PATCH /api/folders/:id`，把 `icon` 设为返回的 `url`；
3. 文件夹树立即刷新，显示新图标。

### 3.3 图标面板结构

面板顶部是**三个来源标签页**，默认停在 Emoji：

```
┌───────────────────────────────┐
│ 😀 Emoji │ 🔷 品牌 │ 🖼 图片  │  ← 标签页，默认 Emoji
├───────────────────────────────┤
│  📚 📁 💡 🎯 🌱 🧠 🛠 🧪     │  ← Emoji 页
│  🎨 📝 📌 🚀 🧩 🔒 🗂         │
├───────────────────────────────┤
│  [恢复默认]        [取消]      │
└───────────────────────────────┘

切到「品牌」（与 Emoji 页一样按分组展示）：
┌───────────────────────────────┐
│ [搜索分类或图标：前端 / Go…]   │
│ 语言                            │  ← 分组标题
│  🟦 🐍 ☕ 🦀 🟨 🟪 🟥 …     │
│ 前端                            │
│  🟩 ⚛️ 🅰️ 🧡 🚀 …           │  ← 带品牌色，可滚动
└───────────────────────────────┘

切到「图片」：
┌───────────────────────────────┐
│ ┌────┐ 当前使用的图片           │  ← 已设置图片图标时显示预览
│ │ 🖼 │                        │
│ └────┘                        │
│ [ 选择图片 ]  [ 移除 ]         │
│ 支持 png / jpeg / gif / webp， │
│ 最大 10 MiB；也可直接粘贴       │
└───────────────────────────────┘
```

**三个标签页互相独立**：

| 页 | 内容 | 已选图标时显示 |
|---|---|---|
| Emoji | 326 个内置 emoji，分 10 组，可按分组名搜索 | — |
| 品牌 | 127 个品牌 logo，分 6 组，可按分类名或图标名搜索 | — |
| 图片 | 上传入口 + 当前图片预览 + 移除 | 预览与「移除」按钮 |

**没有文本框**：Emoji 从内置列表点选，或直接在面板上粘贴（见 3.3.2）。

### 3.3.2 粘贴

面板整体监听 `paste`：

- 剪贴板里有 `image/*` → 上传并设为图标；
- 否则取 `text/plain`，**长度不超过 16 个字符**时当作 Emoji 保存；
- 其他情况不接管，避免复制一段正文后误把整段文字设成图标。

### 3.4 品牌图标库

- 数据来自 `simple-icons`，**用 `?raw` 按需引入**：只打进 `utils/brand-icons.ts` 里列出的 127 个；
- **不导入整个图标库**（16 MB、3000+ 图标），否则构建与首屏都会明显变慢；
- **按用途分 6 组**：语言、前端、后端、数据、运维、工具；
- 搜索规则：命中分组名（如「前端」）返回整组；否则按图标 key / 显示名过滤，命中的图标保留在原分组里；
- `folders.icon` 存的是图标 **key**（如 `go`），而不是 SVG 源码；
- 渲染时按 key 查表，找不到就退回 emoji 渲染。

**品牌色**：每个图标带 simple-icons 官方的品牌色（如 Go `#00ADD8`、Python `#3776AB`）。官方色为纯黑或近黑的图标（OpenJDK、Rust、Next.js、Kafka 等）统一换成 `currentColor`，否则深色主题下看不见。

**两处渲染共用同一套配色**：图标面板与文件夹树都通过 `--brand-color` 传递颜色，`fill: var(--brand-color, currentColor)` 消费。新增展示位置时复用这个 CSS 变量，不要另写一份。

**体积**：127 个 SVG 使 `NoteListPanel` chunk 从约 22 KB 增到约 208 KB（gzip 后更小），且该 chunk 按路由懒加载。

### 3.5 展示

| `icon` 值 | 渲染 |
|---|---|
| `null` / 空 | 默认文件夹线条图标 |
| 以 `/` 开头 | `<img>`，尺寸 16×16，`object-fit: contain` |
| 命中品牌 key（如 `go`） | 内联 SVG，`fill: currentColor` |
| 其他 | 按文本渲染（emoji） |

**图片加载失败时回退到默认图标**，不显示破图。

## 四、样式

- 上传按钮沿用现有 `.btn` 样式；
- 树里的图标容器尺寸不变（16×16），图片 `object-fit: contain`，避免拉伸变形；
- 不引入新的颜色或圆角体系。

## 五、不做的事

- 不做拖拽调整图片尺寸；
- 不做图片裁剪；
- 不做上传进度条（文件小，耗时短）；
- 不做图片管理页面；
- 不做 SVG 上传。
