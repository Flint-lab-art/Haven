# data-model — 四期 schema 变更

> 本文件回答：四期对数据库表结构做了哪些改动（v1–v3 未覆盖的部分）。
> 依赖：`../../v1/backend/data-model.md`、`../v3/backend/data-model.md`

覆盖规则见 `../../README.md` 第二节。

## 一、folders.icon 语义扩展

**不新增列、不新增表。** 只扩展 `folders.icon` 允许存放的内容：

| 取值形态 | 含义 | 渲染方式 |
|---|---|---|
| `NULL` | 未设置 | 默认文件夹图标 |
| 以 `/` 开头 | 图片路径（如 `/uploads/2026/11/abc.png`） | `<img>` |
| 其他非空文本 | Emoji 或图标名（如 `📚`） | 文本渲染 |

**规则**：

1. **向后兼容**：现有 emoji 数据继续有效，不需要迁移。
2. **长度上限调整**：现为 16 rune，图片路径可能更长；本期放宽到 **256 rune**（路径长度，不是文件大小）。
3. **不校验文件是否存在**：文件夹图标指向的文件若已被删除，前端回退显示默认图标，不报错。
4. **不做外键**：`icon` 不是关联，是纯文本，指向的关系由约定而非约束保证。

## 二、笔记正文

**表结构不变。** 变化在写入约定：

- 图片以 `/uploads/...` 形式出现在 `notes.content` 的 Markdown 里；
- **不再接受** `data:image/...;base64,` 内嵌形式作为新写入（历史数据不做迁移）；
- `search_text` 生成列因此不再包含图片数据，trigram 索引只覆盖真实文本。

## 三、migration 规划

**本期没有 migration。**

`folders.icon` 是 `text` 类型，长度限制只在应用层常量 `folders.MaxIconRunes`（现值 16）。本期把它调到 256 即可，数据库无需改动。
