# README — Haven 文档索引

> 本文件回答：Haven 的文档分几期、各期文档放在哪、v1 与 v2 之间是什么关系、生成代码时该读哪些文件。
> 依赖：无

本目录是 Haven 的**文档来源**，按期（版本）分文件夹：

```
docs-ai/
├── README.md      # 本文件：索引 + 覆盖规则（唯一出处）
├── v1/            # 第一期文档（已冻结，与当前代码一一对应）
└── v2/            # 第二期文档（增量，只写二期新增与变更）
```

## 一、分期原则

- **v1 是已完成并已落地的版本**，文档与 `backend/`、`frontend/` 的现有代码一一对应。
- **v2 是第二期**，在当前代码基础上演进。v2 只写**二期新增和变更的部分**，不复述 v1 已有的设计。
- **v2 不修改 v1。** v1 作为第一期实现参考永久保留。
- v2 内部目录结构与 v1 **完全镜像**：文件名相同意味着「对应同一个问题的二期版本」。

## 二、v2 的覆盖规则（本节是唯一出处）

v2 是 v1 的**增量覆盖层**，按以下顺序理解：

1. **逐节覆盖，粒度是「节」不是「文件」。** v2 某文件里出现的某一节，替换 v1 同名文件里的同名节；v2 文件里没有出现的节，v1 原样有效。
2. **文件级等同「全部替换」。** 若整节替换，必须在该节开头写明「本节整节替换 v1 同名节，以本文件为准」。
3. **v2 里没提的，一律按 v1 执行。** 包括：路由、字段、错误码、禁令、常量、目录结构。
4. **新增优先。** 同一问题在 v1 与 v2 都写到时，v2 优先，且 v2 必须说明「这与 v1 哪一节不同」。
5. **禁令同样适用覆盖规则，但必须显式解除。** v1 `conventions.md` 第四节的禁令默认继续有效；要做什么而 v1 明文禁止的，必须在 `v2/conventions.md` 第二节登记「解除哪条、理由、日期」。
6. **冲突处理**：v1 与 v2 出现无法用上面规则判定的矛盾时，不要自行取舍，停下来问人类。

## 三、v1 已过期的表述怎么处理

v1 里「本期不做、第二版再做」的表述，若二期实现，**不改 v1**，而是在 `v2/changes.md` 登记「v1 的哪个文件、哪一节、被什么替代」。

## 四、生成代码时读哪些文件

依据 `v1/conventions.md` 第三节的上下文规则，二期的上下文是**v1 全文 + v2 全文**：

- **后端**：`v1/` 根下项目级文件 + `v1/backend/` + `v1/api.md`，叠加 `v2/api.md`、`v2/conventions.md`、`v2/backend/`；
- **前端**：`v1/` 根下项目级文件 + `v1/frontend/` + `v1/api.md`，叠加 `v2/api.md`、`v2/conventions.md`、`v2/frontend/`；
- **优先级**：以第二节的覆盖规则为准。

二期的代码**仍在同一个 `backend/`、`frontend/` 仓库里增量演进**，不新建并列目录。

## 七、维护规则

- 本目录的修改只由人类完成，AI 只读。
- 新增文档前，先在第五节登记一行，再创建文件；每个文件开头保留固定两行（`本文件回答` / `依赖`）。
- 文档归属按 `v1/conventions.md` 第一节判断（约束后端 → `backend/`，约束前端 → `frontend/`，共享 → 根）。
